Design Thinking · แมพใหม่ + ข้อมูลผู้เล่น

Meteor Crater Concepts

ผลล่าสุด: เลือกแบบ A หลุมอุกกาบาต · ผังแบบวงล้อเดิมใช้ได้ แต่หน้าตาคล้ายเกมฟาร์มที่มีอยู่แล้ว หน้านี้คิดใหม่ตาม Design Thinking 5 ขั้น โดยเอาเสาพลังออก ให้กลางแมพเป็นแค่จุดที่บอสเกิด และตอบเรื่องอัปสกิลกับอัปตัวเองในมุมฐานข้อมูล

STEP 1–2 · EMPATHIZE + DEFINE

ผู้เล่นเป็นใคร และโจทย์คืออะไร

ผู้เล่นหลัก [Assumed]

  • ต้น, 11 ปี, มือถือ เล่นครั้งละ 15–30 นาที เข้าตามเพื่อน ต้องเข้าใจในไม่กี่วินาที ไม่ชอบอ่านเยอะ
  • มายด์, 16 ปี, PC อยากติดท็อปดาเมจ ชอบมีเป้าหมายระยะยาว ยอมเติมถ้าคุ้ม
  • คนเปิด AFK เปิดทิ้งไว้ อยากได้ของโดยไม่โดนคนอื่นแย่งหรือกลั่นแกล้ง

ยังไม่ได้คุยกับผู้เล่นจริง ควรยืนยันจากเพื่อนหรือน้องที่เล่น Roblox 3–5 คน

Problem Statement

ผู้เล่นอายุ 9–25 ต้องการแมพที่ดูครั้งแรกแล้วรู้ว่าเป็นเกมตีบอสด้วยป้อม และได้ของเท่าเทียมกัน เพราะผังฐานเรียงวงดูเหมือนเกมฟาร์ม และของที่ต้องแย่งกันทำให้คน AFK หรือเด็กเล็กเสียเปรียบ

How Might We

  1. ทำให้การมาของบอสเป็นภาพที่คนจำได้และแชร์ต่อ
  2. ให้ทุกฐานได้ของเท่ากันโดยไม่ต้องแย่ง
  3. ให้ภาพปกเกม (thumbnail) ต่างจากเกมฟาร์มทันที
  4. ให้ผู้เล่นใหม่รู้ใน 30 วินาทีว่าฐานไหนของตัวเองและต้องทำอะไร
STEP 3 · IDEATE

13 ไอเดีย จัดลงตาราง 4 ช่อง

แกนตั้งถามว่าผู้เล่นจะตื่นเต้นไหม แกนนอนถามว่ามีเกมอื่นทำแล้วหรือยัง ชื่อเกมตัวอย่างเป็นความจำของผม ควรค้นใน Discovery ยืนยัน [Unverified]

⭐ จุดขาย · น่าสนใจ + ใหม่

  1. บอสอุกกาบาต บอสพุ่งลงจากฟ้าลงหลุมกลางแมพ มีวงเงาเตือนก่อน 10 วินาที
  2. สวนหลังบ้านส่วนตัว ของเกิดในเขตหลังฐานใครฐานมัน ไม่มีการแย่ง
  3. เศษอุกกาบาต ตีบอสชนะแล้วเศษตกลงทุกฐานเท่ากัน เป็นของหายาก
  4. ป้อมดาว 8 แฉก แมพทั้งแมพเป็นรูปดาว 1 แฉก = 1 ฐาน จำจากภาพปกได้ทันที

✅ พื้นฐาน · น่าสนใจ + มีคนทำแล้ว

  1. ฐานล้อมรอบบอส เหมือนเกมฟาร์ม/tycoon
  2. เดินเก็บของกลับมาขาย แนว Simulator
  3. มอนเดินตามทางให้ป้อมยิง แนว Tower Defense
  4. ท้องฟ้ามืดลงตอนบอสมา event ทั่วไป ทำง่าย ได้บรรยากาศ

💡 ปรับก่อน · ใหม่แต่ยังมีปัญหา

  1. เกาะลอย + สะพาน สวยมาก แต่มือถือกระโดดพลาดตกบ่อย
  2. ฐานหมุนเหมือนม้าหมุน ผู้เล่นยืนบนพื้นที่เคลื่อนที่ ฟิสิกส์มีปัญหา
  3. หุบก้นหอย มอนเดินวนเข้าหาบอส แต่ฐานห่างบอสไม่เท่ากัน

✖ ตัดทิ้ง

  1. เสาพลังกลาง คุณตัดสินแล้ว: ทำให้เหลื่อมล้ำ
  2. บอสเกิดสุ่มใกล้ฐานใดฐานหนึ่ง ไม่ยุติธรรม และไม่ใหม่

สูตรที่แนะนำ

ใช้แกน ✅ ข้อ 5+6+7 ที่ผู้เล่นคุ้นอยู่แล้ว แล้วเติมจุดขาย ⭐ ข้อ 1+2 คือ "หลุมอุกกาบาต" ด้านล่าง ถ้าอยากให้ภาพปกแปลกกว่านี้ให้ใช้ข้อ 4 "ป้อมดาว" สองแบบนี้ใช้สวนหลังบ้านส่วนตัวได้เหมือนกัน

STEP 4 · PROTOTYPE

3 แมพต้นแบบ

ผู้เล่นทำอะไร (30 วินาทีแรก)

    ข้อควรระวัง

      ข้อมูลผู้เล่น

      ร้านอัปสกิล กับ อัปตัวเอง

      ทั้งสองอย่างต้องเก็บใน DataStore แต่ความเสี่ยงต่างกันมาก ผมแนะนำให้ แยกเป็นคนละตาราง และให้ อัปที่ฐานตัวเอง (ป้ายอัปเกรดหน้าบ้าน) แทนร้านกลางแมพ เพราะกลางแมพเหลือไว้ให้บอสอย่างเดียว และไม่มีใครไปยืนบังร้าน

      อัปตัวเอง (ซื้อด้วยเงิน)สกิลป้อม (กาชา)
      ตัวอย่างป้อม · กระเป๋า · แม็กกาซีน · บ้าน · ความเร็วเดินOverdrive, HeavyRounds, BossBreaker …
      ได้มาอย่างไรจ่ายเงินตามราคาใน Economy.luau ได้แน่นอนสุ่มจากตั๋ว ได้ซ้ำได้
      เก็บอะไรเลขเลเวลอย่างเดียว เช่น Bag = 3เลเวล + จำนวนชิ้นซ้ำ ต่อสกิล (มีแล้วใน v3)
      ความเสี่ยงต่ำ: ผิดพลาดก็แค่เลเวลเพี้ยน คำนวณใหม่ได้สูง: ถ้าขายตั๋วด้วย Robux เงินจริงเกี่ยว ต้องกันได้ของซ้ำ/ไม่ได้ของ
      อยู่ตรงไหนในแมพป้ายอัปเกรดหน้าบ้านของตัวเองตู้กาชาข้างบ้าน (หรือเมนูในจอ)

      โครงข้อมูลที่เสนอ (v4) [Proposed]

      ป้อมมี TurretLevel อยู่แล้ว ให้คงไว้ที่เดิม ไม่ต้องย้ายเข้า Upgrades ย้ายตอนนี้ได้ประโยชน์น้อยแต่ต้องเขียน migration เพิ่มโดยไม่จำเป็น

      เตือนล่วงหน้า

      เรื่องข้อมูลที่มือใหม่มักพลาด

      เรียงจากเสียหายมากไปน้อย ติ๊กเขียว = โค้ดตอนนี้ทำถูกแล้ว ให้รักษาไว้

      • สำคัญมากขายตั๋วกาชาด้วย Robux ต้องบันทึกให้สำเร็จก่อนตอบว่า "ให้ของแล้ว"ProcessReceipt ต้องเพิ่มตั๋วลงข้อมูลและบันทึกผ่านก่อน จึงคืนค่า PurchaseGranted และต้องจำ PurchaseId ที่ให้ไปแล้วเพื่อไม่ให้ได้ซ้ำ ถ้าพลาดคือผู้เล่นจ่ายเงินแล้วไม่ได้ของ [Verified]
      • สำคัญมากยังไม่มี session lock ต้องทำก่อนเปิดแลกเปลี่ยนอุปกรณ์ถ้าผู้เล่นย้ายเซิร์ฟเร็วๆ เซิร์ฟเก่าอาจบันทึกทับข้อมูลใหม่ ของที่ส่งให้คนอื่นแล้วจะกลับมา (ของซ้ำ) PlayerData.luau เขียนเตือนไว้แล้ว [Inferred]
      • สำคัญมากเพิ่ม field ใหม่ทุกครั้ง ต้องครบ 3 อย่างเพิ่มใน DEFAULT · เพิ่ม VERSION ขึ้น 1 · เขียน MIGRATIONS[เลขเดิม] ห้ามเปลี่ยนชื่อหรือลบ field เดิมโดยไม่มี migration ไม่งั้นของผู้เล่นเก่าหาย
      • ควรระวังทดสอบใน Studio แยก DataStore จากของจริงStudio ที่เปิด API Access ใช้ DataStore เดียวกับเกมจริง ถ้าเทสต์แจกเงินตัวเองจะไปอยู่ในเกมจริงด้วย ควรใช้ชื่อ store แยกตอนอยู่ใน Studio เช่น PlayerData_Dev [Inferred]
      • ควรระวังเงิน idle ตอนออฟไลน์ ใช้เวลาของ Server และมีเพดานใช้ os.time() ฝั่ง Server เท่านั้น (ห้ามรับเวลาจาก Client) และจำกัดชั่วโมงสูงสุด ไม่งั้นคนหายไปเดือนเดียวกลับมารวยทันที
      • ควรระวังRebirth ต้องเขียนให้ชัดว่าอะไรรีเซ็ต อะไรเก็บไว้ทำเป็นรายการใน Config เช่น รีเซ็ต Coins / TurretLevel / Upgrades · เก็บ Skills / Gear / Rebirths ทำในคำสั่ง update เดียว
      • ควรระวังตาราง key ต้องเป็นข้อความทั้งหมด หรือเป็นลำดับ 1,2,3 ไม่มีช่องว่างตารางที่ key ผสมเลขกับข้อความ หรือเลขข้ามช่อง จะบันทึกไม่ได้หรือข้อมูลหาย เก็บ Instance/Color3/Vector3 ลงไปตรงๆ ก็ไม่ได้ [Verified]
      • ควรระวังตารางคะแนนดาเมจของแต่ละบอสไม่ต้องบันทึกเป็นข้อมูลรอบเดียว ถ้าจะมีกระดานอันดับทั้งเกมให้ใช้ OrderedDataStore แยก ไม่ยัดรวมในข้อมูลผู้เล่น
      • ทำถูกแล้วซื้อของ = เช็กเงิน + หักเงิน + ให้ของ ใน update เดียวTurretService.upgrade ทำแบบนี้แล้ว ระบบ Upgrades ใหม่ให้เขียนแบบเดียวกัน ราคาดึงจาก Config ไม่รับราคาจาก Client
      • ทำถูกแล้วโหลดไม่สำเร็จไม่บันทึกทับ · ครอบ pcall + retry · ตรวจชนิดข้อมูลที่โหลดมามีครบใน PlayerData.luau
      • ทำถูกแล้วเก็บเลเวล ไม่เก็บค่าพลังดาเมจคำนวณจาก TurretLevel + Config ทำให้ปรับ Balance ได้โดยไม่ต้องแก้ข้อมูลผู้เล่น
