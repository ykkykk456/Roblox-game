# PRINCIPLES — กฎเหล็กขององค์กร

**โครงการ:** Roblox AI Development Organization
**สถานะ:** Active

> กฎเหล็กใช้กับ **ทุกบทบาท ทุกงาน ทุก Phase**
> การแก้ไขหรือยกเว้นกฎใดๆ ต้องเป็นการตัดสินใจของ CEO เท่านั้น (ดู `ROLES.md`)

| ข้อ | กฎเหล็ก | สาระสำคัญ |
|---|---|---|
| 1 | Roblox Security (Server Authority) | Server ตัดสิน Client ไม่ถูกเชื่อถือ |
| 2 | Data Safety (Validation & Fallback) | ตรวจสอบข้อมูลทุกจุด และมีทางสำรองเสมอ |
| 3 | Evidence System | ทุกข้อเท็จจริงต้องมีสถานะหลักฐาน |

---

## กฎเหล็กข้อ 1: Roblox Security (Server Authority)

**หลักการ:** Server คือแหล่งความจริงเพียงแหล่งเดียว (single source of truth) ส่วน Client ต้องถือว่าไม่น่าเชื่อถือเสมอ เพราะโค้ดและข้อมูลฝั่ง Client ผู้เล่นเข้าถึงและแก้ไขได้

**ต้องทำ**
- ตรรกะและสถานะที่มีผลต่อเกม ต้องตัดสินและเก็บที่ **Server**
- Client ทำได้เพียง 3 อย่าง: รับ Input, แสดงผล (UI/เอฟเฟกต์), ส่ง "คำขอ" ไปยัง Server
- ข้อมูลที่มาจาก Client ผ่าน RemoteEvent / RemoteFunction ต้อง **validate ที่ Server ทุกครั้ง** ทั้งชนิดข้อมูล ช่วงค่า สิทธิ์ และความเป็นไปได้ตามสถานะจริง
- Client ส่ง "เจตนา" แล้วให้ Server คำนวณผลลัพธ์ ไม่ใช่ให้ Client ส่ง "ผลลัพธ์"
- ข้อมูลลับและ logic สำคัญ ต้องอยู่ในที่ที่ Client เข้าถึงไม่ได้
- ออกแบบ Remote ให้ให้สิทธิ์น้อยที่สุด (least privilege) และจำกัดอัตราการเรียก (rate limit)

**ห้ามทำ**
- ห้ามเชื่อค่าที่ Client ส่งมาโดยไม่ตรวจสอบ
- ห้ามให้ Client กำหนดค่าที่มีผลต่อผู้เล่นโดยตรง (เช่น สกุลเงิน, ไอเทม, สิทธิ์)
- ห้ามวางข้อมูลลับหรือ logic สำคัญไว้ฝั่ง Client

**Checklist ก่อนส่งงาน**
- [ ] ผลลัพธ์สำคัญทุกอย่างถูกตัดสินที่ Server
- [ ] ทุก Remote มีการ validate ข้อมูลขาเข้าที่ Server
- [ ] ไม่มีข้อมูลลับหรือ logic สำคัญฝั่ง Client

## กฎเหล็กข้อ 2: Data Safety (Validation & Fallback)

**หลักการ:** ข้อมูลต้องไม่เสียหายและไม่ทำให้ระบบล้ม แม้ข้อมูลผิดรูปแบบ หายไป หรือโหลดไม่สำเร็จ

**Validation (ตรวจสอบ)**
- ตรวจสอบข้อมูลทุกครั้งที่ข้ามขอบเขต: Client → Server, จากที่เก็บข้อมูล → ระบบ, และก่อนบันทึก
- ตรวจอย่างน้อย: ชนิดข้อมูล, ช่วงค่า, ค่าว่าง/ขาดหาย, โครงสร้างข้อมูล
- ห้ามสมมติว่าข้อมูลจะถูกต้องหรือมีอยู่เสมอ

**Fallback (ทางสำรอง)**
- ต้องมีค่าเริ่มต้นที่ปลอดภัย (safe default) เมื่อข้อมูลหายหรือเสีย
- การดำเนินการที่อาจล้มเหลว (เช่น อ่าน/เขียนข้อมูลถาวร) ต้องมีการจัดการข้อผิดพลาดและ retry ที่เหมาะสม
- **ห้ามบันทึกทับข้อมูลเดิมของผู้เล่น หากการโหลดข้อมูลไม่สำเร็จ**
- ต้องรองรับการเปลี่ยนแปลงโครงสร้างข้อมูลในอนาคตโดยไม่ทำให้ข้อมูลเดิมเสียหาย
- บันทึก log ความผิดพลาดที่เกี่ยวกับข้อมูลเพื่อตรวจสอบย้อนหลัง

**Checklist ก่อนส่งงาน**
- [ ] ทุกจุดที่ข้ามขอบเขตมีการ validate
- [ ] ทุกข้อมูลที่โหลดมามีค่าเริ่มต้นสำรอง
- [ ] ทุกการดำเนินการที่ล้มเหลวได้มีการจัดการข้อผิดพลาด
- [ ] ไม่มีเส้นทางที่บันทึกทับข้อมูลเดิมเมื่อโหลดล้มเหลว

## กฎเหล็กข้อ 3: Evidence System

**หลักการ:** ทุกข้อเท็จจริงสำคัญ โดยเฉพาะเรื่องพฤติกรรมและ API ของ Roblox ต้องระบุสถานะหลักฐานเสมอ

| สถานะ | ความหมาย | ใช้เป็นข้อเท็จจริงได้หรือไม่ |
|---|---|---|
| `[Verified]` | ยืนยันแล้วจากแหล่งที่ตรวจสอบได้ เช่น เอกสาร Roblox ทางการ หรือผลทดสอบจริง | ได้ |
| `[Inferred]` | สรุปอย่างสมเหตุสมผลจากหลักฐาน Verified แต่ไม่ได้ยืนยันตรงๆ | ใช้ระวัง ต้องระบุเหตุผล |
| `[Assumed]` | สมมติฐานที่ใช้ชั่วคราวเพื่อไปต่อ | ไม่ได้ ต้องตรวจสอบภายหลัง |
| `[Proposed]` | ข้อเสนอหรือแบบที่ยังไม่ได้รับอนุมัติ | ไม่ใช่การตัดสินใจ จนกว่าจะอนุมัติ |
| `[Unverified]` | ยังไม่มีหลักฐานหรือไม่ทราบแหล่งที่มา | ไม่ได้ |

**กฎการใช้**
1. ทุกข้อเท็จจริงสำคัญต้องติดสถานะ ทั้งใน Handoff (หัวข้อ Evidence) และในรายงาน
2. ไม่แน่ใจ → ใช้ `[Unverified]` ห้ามใช้ `[Verified]`
3. ห้ามยกระดับสถานะโดยไม่มีหลักฐานรองรับ
4. `[Assumed]` และ `[Unverified]` ห้ามเป็นฐานของงานที่กระทบ Security หรือ Data Safety จนกว่าจะตรวจสอบ หรือได้รับอนุมัติจาก Gemini/CEO
5. `[Proposed]` ต้องรอการอนุมัติก่อนจึงถือเป็นการตัดสินใจ

## ข้อจำกัดบังคับ (Hard Constraints)

> ส่วนนี้ไม่ใช่กฎเหล็กข้อที่ 4 แต่เป็นข้อจำกัดของงานที่ต้องปฏิบัติตามควบคู่กับกฎเหล็ก

### ห้ามใช้ MCP เด็ดขาด

- **ห้ามใช้ MCP (Model Context Protocol) ทุกรูปแบบ** ครอบคลุมการเชื่อมต่อ MCP Server, การเรียกใช้ MCP Tool หรือ Connector และการออกแบบขั้นตอนงานใดๆ ที่ต้องพึ่งพา MCP
- ใช้กับ **ทุกบทบาท ทุกหน่วยงาน ทุก Phase** ไม่มีข้อยกเว้น
- หากงานใดดูเหมือนต้องใช้ MCP → **STOP and REPORT** (ดู `ROLES.md`) ห้ามหาทางอ้อม
- ผลงานที่ละเมิดข้อนี้ถือว่าไม่ผ่านการตรวจรับ

### Roblox เท่านั้น

- องค์กรนี้พัฒนาเกม Roblox เท่านั้น งานสำหรับแพลตฟอร์มหรือเอ็นจินอื่นอยู่นอกขอบเขต

## Principle Check (ก่อนส่งงานทุกครั้ง)

- [ ] Server Authority: ผ่าน
- [ ] Data Safety: ผ่าน
- [ ] Evidence System: ข้อเท็จจริงสำคัญทุกข้อมีสถานะ
- [ ] ไม่ใช้ MCP
- [ ] อยู่ใน Scope ที่ได้รับมอบหมาย
