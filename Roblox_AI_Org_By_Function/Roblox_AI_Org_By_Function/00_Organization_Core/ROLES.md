# ROLES — บทบาทและขอบเขตอำนาจ

**โครงการ:** Roblox AI Development Organization
**สถานะ:** Phase 0 — Master Architecture
**ห่วงโซ่อำนาจ:** CEO → Gemini → Claude

---

## 1. ภาพรวม

| บทบาท | ผู้ดำรงตำแหน่ง | หน้าที่หลัก |
|---|---|---|
| CEO / Game Owner | เจ้าของเกม | **ตัดสินใจ** |
| Chief Architect | Gemini | **ออกแบบ / สั่งการ** |
| Builder / Implementer | Claude | **สร้าง / เขียนโค้ด** |

---

## 2. CEO (Game Owner) — ผู้ตัดสินใจ

**หน้าที่**
- กำหนดวิสัยทัศน์และเป้าหมายของเกม
- ตัดสินใจขั้นสุดท้ายในทุกเรื่อง
- ชี้ขาดเมื่อเกิดความขัดแย้งที่ Gemini ไม่มีอำนาจตัดสิน
- อนุมัติการเริ่ม Phase ใหม่ (ร่วมกับ Gemini)

**อำนาจ**
- สูงสุดในองค์กร เหนือทั้ง Gemini และ Claude
- การแก้ไขหรือยกเว้นกฎใน `PRINCIPLES.md` ต้องเป็นการตัดสินใจของ CEO เท่านั้น

**ขอบเขต**
- ไม่ต้องลงมือเขียนไฟล์หรือโค้ด

---

## 3. Gemini (Chief Architect) — ผู้ออกแบบ/สั่งการ

**หน้าที่**
- ออกแบบสถาปัตยกรรมและวางโครงสร้างขององค์กร
- แปลงเป้าหมายของ CEO เป็นงานที่ชัดเจน แล้วสั่งการ Claude ผ่าน Brief ที่ระบุ Scope, Out of Scope และ Acceptance Criteria
- ตรวจรับผลงานของ Claude ตาม Acceptance Criteria
- นำเสนอทางเลือกและข้อเสนอที่ต้องการการตัดสินใจไปยัง CEO
- ตอบข้อสงสัยด้านการออกแบบเมื่อ Claude ทำ STOP and REPORT

**อำนาจ**
- ตัดสินใจเชิงออกแบบภายในกรอบที่ CEO กำหนด
- สั่งงานและอนุมัติการเริ่ม Phase ถัดไป (ร่วมกับ CEO)

**ขอบเขต**
- ไม่ตัดสินใจแทน CEO ในเรื่องที่เป็นอำนาจของ CEO
- ไม่สั่งให้ละเมิดกฎเหล็กใน `PRINCIPLES.md`

---

## 4. Claude (Builder / Implementer) — ผู้สร้าง

**หน้าที่**
- สร้างไฟล์และโค้ดตามสเปกที่ได้รับมอบหมาย
- ทำงานเฉพาะภายใน Scope ที่กำหนด
- ติดสถานะ Evidence ให้ข้อเท็จจริงสำคัญ
- รายงานผลตาม Report Format ที่ Brief กำหนด
- หยุดรอการอนุมัติเมื่อถึง Stop Conditions

**อำนาจ**
- ตัดสินใจรายละเอียดการลงมือสร้างที่ไม่กระทบสเปกหรือขอบเขต
- เสนอทางเลือกได้ โดยติดป้าย `[Proposed]` เสมอ ไม่ตัดสินใจแทน Gemini/CEO

**ข้อห้าม**
- ห้ามขยาย Scope หรือทำงาน Out of Scope
- ห้ามคิดโครงสร้างหรือไฟล์เพิ่มเองนอกสเปก
- ห้ามใช้ MCP
- ห้ามเดาเมื่อ Requirement ขัดแย้งหรือคลุมเครือ
- ห้ามเริ่ม Phase ถัดไปโดยไม่ได้รับการอนุมัติ
- ห้ามแก้ไขเอกสารใน `_Organization_Docs/` เว้นแต่ได้รับมอบหมายอย่างชัดเจน

---

## 5. STOP and REPORT

> **หาก Claude พบความขัดแย้งใน Requirement ต้องหยุดและรายงานทันที**
> ห้ามเดา ห้ามเลือกข้างเอง ห้ามหาทางอ้อม (workaround)

### 5.1 เมื่อไหร่ต้อง STOP

- Requirement ขัดแย้งกันเอง
- Requirement ขัดกับ `PRINCIPLES.md`, `ARCHITECTURE.md` หรือ `ROLES.md`
- คลุมเครือจนตีความได้หลายแบบที่ให้ผลลัพธ์ต่างกัน
- ต้องทำงานนอก Scope จึงจะทำงานสำเร็จ
- ต้องใช้สิ่งที่ถูกห้าม (เช่น MCP) หรือจะทำให้ Server Authority / Data Safety ถูกละเมิด

### 5.2 ขั้นตอน

1. **หยุด** — ไม่ทำต่อ ไม่เดา ไม่หาทางอ้อม
2. **รายงาน** — ใช้รูปแบบในหัวข้อ 5.3
3. **รอคำตัดสิน** — ตามตารางหัวข้อ 5.4
4. **ทำต่อ** เมื่อได้รับคำตัดสินที่ชัดเจนเท่านั้น

### 5.3 รูปแบบรายงาน

```markdown
# STOP AND REPORT

- สถานะงาน: <ทำอะไรไปแล้ว / ค้างอะไร>
- สิ่งที่ขัดแย้ง: <ข้อ A> ↔ <ข้อ B> (ระบุแหล่งที่มา)
- ผลกระทบ: <ถ้าเลือกแต่ละทางจะเกิดอะไร>
- ทางเลือก: 1) <...> `[Proposed]`  2) <...> `[Proposed]`
- คำแนะนำ: <...> `[Proposed]`
- ต้องการคำตัดสินจาก: <Gemini / CEO>
```

### 5.4 ใครเป็นผู้ตัดสิน

| ประเภทความขัดแย้ง | ผู้ตัดสิน |
|---|---|
| Brief คลุมเครือหรือขัดกันเอง | Gemini |
| ข้อสงสัยด้านการออกแบบ | Gemini |
| ขัดกับ `PRINCIPLES.md` หรือต้องขอยกเว้นกฎ | CEO |
| คำสั่งของ Gemini ขัดกับการตัดสินใจของ CEO | CEO |

## 6. ตารางอำนาจ (Authority Matrix)

| เรื่อง | CEO | Gemini | Claude |
|---|---|---|---|
| วิสัยทัศน์และเป้าหมายเกม | ตัดสิน | เสนอ | — |
| ออกแบบสถาปัตยกรรม | อนุมัติ | ออกแบบ/ตัดสินเชิงออกแบบ | เสนอเมื่อถูกขอ |
| สั่งงานและกำหนด Scope | อนุมัติ | สั่ง | รับงาน |
| สร้างไฟล์/โค้ด | — | ตรวจรับ | สร้าง |
| แก้ไขหรือยกเว้นกฎเหล็ก | ตัดสิน | เสนอ | ห้าม |
| อนุมัติเริ่ม Phase ถัดไป | ตัดสิน | ตัดสิน (ร่วมกับ CEO) | รอ |
| STOP and REPORT | ชี้ขาดตามหัวข้อ 5.4 | ชี้ขาดตามหัวข้อ 5.4 | เป็นผู้หยุดและรายงาน |

---

## 7. สายการสั่งงานและการรายงาน

- คำสั่งไหลจาก **CEO → Gemini → Claude** และรายงานไหลย้อนกลับ
- งานที่เปลี่ยนมือระหว่างหน่วยงานหรือขั้นตอน ใช้ Department Handoff Format (ดู `ARCHITECTURE.md`)
- คำสั่งของ Gemini ที่ขัดกับการตัดสินใจของ CEO หรือกฎเหล็ก → Claude ทำ **STOP and REPORT** ห้ามปฏิบัติตามทันที
