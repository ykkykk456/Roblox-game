# 07_QA_Security — QA & SECURITY

## Mission
ตรวจสอบและรับรองอย่างเป็นอิสระว่างานผ่านเกณฑ์คุณภาพและกฎเหล็ก โดยเฉพาะ Server Authority และ Data Safety ก่อนปล่อยเวอร์ชัน

## Responsibilities
- จัดทำและดำเนินการทดสอบตามสเปกและเกณฑ์ตรวจรับ (รวมการใช้งานข้ามอุปกรณ์)
- รีวิวความปลอดภัย: ตรวจว่า Server Authority ถูกบังคับใช้ (เช่น Remote ถูก validate ที่ Server)
- ตรวจ Data Safety (validation, fallback, ไม่บันทึกทับข้อมูลเมื่อโหลดล้มเหลว)
- ตรวจความสอดคล้องของงานที่ประกอบเสร็จกับนโยบายของ Roblox
- รายงานบั๊กและช่องโหว่พร้อมความรุนแรงและหลักฐาน (สถานะ Evidence)
- ออกผล Pass/Fail เป็นเงื่อนไขก่อนปล่อยเวอร์ชัน

## Non-responsibilities
- แก้โค้ดหรือแก้บั๊กเอง (QA รายงาน CTO เป็นผู้แก้) → **05_CTO**
- วิเคราะห์ข้อมูลผู้เล่น ตลาด หรือตัวชี้วัดหลังปล่อย (Data analytics ไม่ใช่ QA) → **03_Market_Data**
- ตัดสินฟีเจอร์หรือแก้สเปกประสบการณ์ → **02_Product_UX**
- ปรับค่า Balance หรือตัวเลขเศรษฐกิจ (QA รายงานความผิดปกติได้) → **04_CFO**
- สร้างหรือแก้ asset → **06_Art_Audio**
- ตัดสินว่าจะปล่อยเวอร์ชันหรือไม่ → **01_CEO**

## Inputs
- จาก **02_Product_UX**: สเปกและเกณฑ์ตรวจรับ
- จาก **05_CTO**: ผลงานที่สร้างเสร็จ
- จาก **06_Art_Audio**: ทะเบียน Asset ID ที่ใช้
- จาก **04_CFO**: ค่าเศรษฐกิจสำหรับตรวจความสอดคล้อง
- จาก `PRINCIPLES.md`: เกณฑ์ Server Authority และ Data Safety

## Outputs
- ส่งไป **05_CTO**: รายงานบั๊กและช่องโหว่พร้อมหลักฐาน
- ส่งไป **01_CEO**: ผล Pass/Fail และความเสี่ยงคงเหลือ
- ส่งไป **08_Operations**: สถานะการตรวจรับ เพื่อประสานกำหนดการ
- ส่งไป **02_Product_UX**, **04_CFO**, **06_Art_Audio**: ความผิดปกติที่พบในขอบเขตของแผนกนั้น

## Escalation Rules
หยุดงานที่เกี่ยวข้องและส่งให้ CEO ตัดสินใจเมื่อ:
- พบช่องโหว่รุนแรงที่ละเมิด Server Authority หรือ Data Safety และยังไม่ถูกแก้
- มีแรงกดดันให้ปล่อยเวอร์ชันทั้งที่ผลตรวจไม่ผ่าน
- ตกลงกับ 05_CTO ไม่ได้ว่าสิ่งที่พบเป็นบั๊กหรือช่องโหว่หรือไม่
- งานขัดกับ `PRINCIPLES.md` หรือไม่มีแผนกใดเป็นเจ้าของชัดเจน
