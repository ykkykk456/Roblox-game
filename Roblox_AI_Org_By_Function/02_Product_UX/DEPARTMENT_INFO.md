# 02_Product_UX — PRODUCT & UX DESIGN

## Mission
กำหนดว่าเกมมีฟีเจอร์อะไรและผู้เล่นสัมผัสประสบการณ์อย่างไร โดยส่งมอบสเปกที่แผนกอื่นนำไปสร้างต่อได้

## Responsibilities
- แปลง Game Direction เป็นสเปกฟีเจอร์และ user flow
- ออกแบบ UX เชิงโครงสร้าง (โครงหน้าจอ การนำทาง การไหลของผู้เล่น)
- ออกแบบให้รองรับหลายอุปกรณ์บน Roblox (มือถือ/PC/คอนโซล) และรูปแบบการควบคุมที่ต่างกัน
- ออกแบบประสบการณ์ของผู้เล่นใหม่ตั้งแต่เข้าเกมครั้งแรก
- ระบุจุดที่ฟีเจอร์เกี่ยวข้องกับเศรษฐกิจและข้อมูล เพื่อส่งต่อให้ 04_CFO และ 03_Market_Data
- กำหนดเกณฑ์ตรวจรับเชิงประสบการณ์ของแต่ละฟีเจอร์

## Non-responsibilities
- เขียนสคริปต์/โค้ด หรือกำหนดวิธี implement รวมถึงเรื่อง Server/Client Authority → **05_CTO**
- กำหนดตัวเลข Balance ราคา หรือรางวัล → **04_CFO**
- สร้างหรือกำกับ asset ภาพและเสียง รวมถึงกำหนดหน้าตา (visual) ของ UI → **06_Art_Audio**
- วิเคราะห์ข้อมูลผู้เล่นหรือตลาด → **03_Market_Data**
- ทดสอบฟีเจอร์หรือรีวิวความปลอดภัย → **07_QA_Security**
- ตัดสินวิสัยทัศน์หรือลำดับความสำคัญ → **01_CEO**

## Inputs
- จาก **01_CEO**: Game Direction และลำดับความสำคัญ
- จาก **03_Market_Data**: insight ผู้เล่นและตลาด
- จาก **04_CFO**: ค่าและข้อจำกัดทางเศรษฐกิจที่ฟีเจอร์ต้องรองรับ
- จาก **05_CTO**: ข้อจำกัดทางเทคนิคของ Roblox ที่กระทบการออกแบบ
- จาก **07_QA_Security**: ปัญหาด้านประสบการณ์ที่พบระหว่างทดสอบ

## Outputs
- ส่งไป **05_CTO**: สเปกฟีเจอร์ user flow และเกณฑ์ตรวจรับ
- ส่งไป **06_Art_Audio**: โครงหน้าจอและความต้องการ asset ของฟีเจอร์
- ส่งไป **04_CFO**: จุดเชื่อมต่อกับเศรษฐกิจของแต่ละฟีเจอร์
- ส่งไป **03_Market_Data**: คำถามที่ต้องการให้ข้อมูลตอบ
- ส่งไป **07_QA_Security**: สเปกและเกณฑ์ตรวจรับเป็นฐานการทดสอบ

## Escalation Rules
หยุดงานที่เกี่ยวข้องและส่งให้ CEO ตัดสินใจเมื่อ:
- ฟีเจอร์ขัดกับ Game Direction หรือลำดับความสำคัญที่ CEO กำหนด
- ข้อจำกัดทางเทคนิคทำให้สเปกต้องเปลี่ยนใหญ่จนกระทบวิสัยทัศน์
- ประสบการณ์ผู้เล่นขัดกับกลยุทธ์รายได้ และตกลงกับ 04_CFO ไม่ได้
- งานขัดกับ `PRINCIPLES.md` หรือไม่มีแผนกใดเป็นเจ้าของชัดเจน
